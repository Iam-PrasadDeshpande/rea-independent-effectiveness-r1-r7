## Questions and method

This research asks three separate questions: what REA actually inspected and retained; what Codex reconstructed correctly; and what adding REA changed relative to conventional tools. A is ordinary inspection, B adds direct tools, and C adds REA. R1 has A/C only. The case set is deliberately varied and not statistically representative. Reference behavior and hidden contracts differ by case. Controllers, amendments, recovery attempts and limitations remain part of the record. [Methodology](../RESEARCH-METHODOLOGY.md)

The original evidence audit independently recomputed stored behavioral comparisons where available. This publication audit checked those inputs' current identities, inspected source reports and reconciled packaging/signing. It did not execute applications, tests, oracle programs or investigator code. Architecture grades remain historical model/coordinator judgments; no external human gold, independent laboratory or statistical replication is claimed. [Historical detailed audit](historical/REA-R1-R7-CONSOLIDATED-FINAL-REPORT.md)

### R2 — Zint GS1-128

A/B/C each match 48 frozen exit/module comparisons on the stripped native target. REA successfully used Ghidra and retained a twelve-record, 325,750-byte evidence export. Direct Ghidra also retained identity/address/provider evidence. The forty-fact rubric's FULL/PARTIAL grades were A 33/7, B 37/3, C 39/1; these are coordinator assessments, not general accuracy measures. Common CLI probes and adapter lifecycle confound attribution. Package provenance and pinned source must remain distinct. QUALIFIED_BOUNDED_POC is preserved. ### R3 — Joplin semantic search

The selected valid A/B/C implementations each match forty deterministic search cases. REA primary core analysis timed out at 120 seconds. A successful one-file, 490-byte clipboard analysis cannot qualify the core. C's reconstruction primarily cites ordinary bundle inspection. Architecture points do not establish a REA causal effect. Real-model retrieval quality and native/UI integration remain outside the boundary. EXPERIMENT_COMPLETE_WITH_LIMITATIONS is preserved. [Report and evidence](../experiments/R3-joplin/README.md)

### R4 — SAP AI160

All three timestamp-helper reconstructions match twelve cases. Thirty-eight reference mock/graph checks and five reference fixture UI checks concern different scope and are not extra reconstruction cases. The selected REA feature trace has zero seed matches, with substantial semantic unknowns; absence of matches does not prove feature absence. Note creation is not verified email delivery. Neither the complete purchase-order agent nor live SAP behavior was reconstructed. QUALIFIED_BOUNDED_POC is preserved. [Report and evidence](../experiments/R4-sap-ai160/README.md)

### R5 — Fossify Calendar

A/B/C each pass 32/44 complete scenarios. All recurrence projections match, but all twelve reminder-bearing cases miss the final +1000 ms scheduling adjustment. A additionally mishandles the unsorted-reminder case. Diagnostic analysis of that omission is not a repaired submission or a new score. The original app emulator flow supports selected persistence and alarm observations; notification arrival and a reconstructed Android app remain unqualified. BOUNDED_EXPERIMENT_COMPLETE is preserved. [Report and evidence](../experiments/R5-fossify-calendar/README.md)

Retained normalized counts are A 3/36, B 30/36, C 27/36. ### R7 — Squoosh

All arms match 26/26 positive workflows. Raw A/B grades are 30/30 and C is 29/30. Immutable C29 source and stored execution demonstrate decoding rejection; the lexical evaluator pattern misses “Decoding error,” although the frozen predicate excludes wording. The confirmed false negative is additive; no raw score is replaced.

The permitted original codecs mean this is a bounded browser integration comparison, not reconstruction of compression algorithms or the full editor. REA's identity-bound resize-WASM interface evidence is useful; B obtains the needed interface through direct WABT and A through JavaScript glue. Overall architecture-completeness and correctness gains are not established. PASS_WITH_GAPS is preserved. [Report and correction evidence](../experiments/R7-squoosh/README.md)

## Capability, architecture and efficiency

[Capability coverage](CAPABILITY-COVERAGE.md) records intended, invoked, completed, evidence recovered, behavior validated, incremental gain and limits separately. Successful target analysis coexists with partial coverage, irrelevant summaries and tool-output delivery failures. Underlying engines' decoding/decompilation must not be wholly attributed to REA. Conventional tools also retain evidence.

Functional correctness is assessed only at each frozen boundary. Architecture ratings concern different fact sets and are not pooled. Evidence quality concerns retrievability and provenance; operational reliability concerns invocation, transport and recovery. Token/time records are retained with their original confounds. Complete setup/recovery overhead and billing are not consistently measured. No monetary advantage is inferred. [Architect assessment](ENTERPRISE-ARCHITECT-VERDICT.md)
