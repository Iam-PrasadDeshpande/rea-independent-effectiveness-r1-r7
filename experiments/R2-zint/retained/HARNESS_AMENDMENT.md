# Signing-preserving transport recovery before valid investigations

The initial Arm A attempt (thread 01a14b37-bb3d-7a80-b217-617389718d41) received no callable tools because the available account models all advertise code_mode_only while the JavaScript host was deliberately disabled. It produced no target observations or reconstruction. Its original logs, 30,827 input / 20,096 cached input / 513 output tokens and 23.51 seconds are retained as INVALID setup/recovery evidence, excluded from arm outcomes. The report describes two failed exec discovery attempts; the CLI JSONL exposes no started tool events for these. These attempts are conservatively charged separately.

Recovery does not enable JavaScript, change model metadata or signing policy. In every arm, the same Codex model produces structured JSON action data. Authenticode-verified Windows PowerShell parses and validates this data against the actual scoped MCP catalog, then dispatches literal RPC arguments to the original signed controllers. No model response is executed as an interpreter script or shell command. The genuine REA MCP provider still performs C's native analysis. After each actual response the same arm's Codex thread is resumed, retaining its own context. Session metadata is persisted by vendor Codex to support resume; investigators have no route to other session stores. No auth material is read or copied.

All three valid arms use this transport, the same model/effort, original prompt and budgets. Code Mode and built-in shell stay disabled. Available catalogs are serialized with name, description and input schema; output schemas are omitted uniformly. Each model-produced action counts as one investigator tool action, including failures. Actual RPC transcripts and cumulative per-turn token usage are retained. Repeated process startup and growing context are measured overhead of this signing-constrained design; they are not attributed to REA alone. No live streaming treatment is claimed.

The original protocol, rubric, 48 cases, two-pass expected results, public cases, binary, initial freeze and failed attempt are preserved unchanged. An additive run-freeze manifest pins this amendment, signed data driver and action schema before any valid arm starts. No source knowledge or original failed A findings enter a valid prompt. This changes orchestration, not the task, oracle, denominator or scoring.
