# Private publication briefing — R7 Squoosh

Status: content prepared for owner review; no LinkedIn publication authorized or performed. Surface: connected technical long-form/post prose for a mixed technical audience. Factual authority is FINAL_REPORT.md and the retained evidence, not tool marketing or investigator self-reports. This briefing concerns R7 only.

## Proposed article

I asked Codex to reconstruct a small image-processing workflow from Squoosh's production assets: load an image, resize it, choose WebP settings and export the result. I wanted to understand where a reverse-engineering tool called REA helps an AI agent do work that can be checked against a real application. Squoosh was a useful target because the feature crosses browser image decoding, JavaScript workers and WebAssembly, the binary code that runs the image-processing codecs in the browser.

The experiment used three separate investigator conversations. One had standard asset inspection, one had direct WebAssembly and JavaScript analysis tools, and one had REA. They received identical pinned application files and the same model configuration and limits. The original source repository, hidden tests and other investigators' outputs were withheld. A separate evaluator had already run and frozen the reference cases before investigation began.

All three produced working integrations that matched the original's encoded bytes and decoded pixels across 26 image workflows. These included different input formats, transparency, resizing filters, color-processing flags and compression settings. The integrations reused the same original codec binaries through independently written worker, loading, memory and export code. That boundary matters: the agents reconstructed the integration around the codecs; they did not recreate the WebP compression algorithm or the complete Squoosh editor.

REA did provide useful evidence. Its WebAssembly inspection attached an exact artifact identity to the imports, exports and typed function interface. That made the resize boundary easier to inspect and trace back to specific bytes. Direct conventional tools also recovered the required interface, while the standard arm found enough information in the JavaScript bundles to implement it. The experiment therefore did not demonstrate a functional reconstruction advantage from REA.

The broader JavaScript analysis was less useful in this case. It produced a large retained record, but some summaries were oriented toward Electron applications rather than this browser codec, and many files were outside the selected analysis. The REA-assisted investigator still relied on direct glue inspection and real browser probes to resolve operational questions. Its report recovered fewer fully supported architecture obligations than the other two reports under the same rubric, so I would not describe this as improved application understanding either.

The evaluation itself needed scrutiny. All three implementations rejected the corrupt image, but the checker missed the REA arm's message, “Decoding error,” because it looked for a different spelling. The frozen requirement concerned decoding rejection and explicitly excluded error wording. We preserved the raw 29/30 result and independently traced the rejection to the submitted image-loading callback rather than quietly changing the score. The other two arms mechanically scored 30/30. This exposed a weakness in the measurement, not a failure of that implementation to reject the image.

Operational costs also need their own evidence. We retained a failed initial tool connection and two signing stalls, and resumed the interrupted investigator without resetting its limits. Input-token totals, cached tokens, output tokens and elapsed time were recorded separately. The REA arm consumed the most input tokens in this run, while its elapsed time was close to the standard arm. A single sequential run on one workstation, with those recovery and cache differences, supports no general speed, cost or superiority claim.

For enterprise AI engineering, the useful distinction here is between a tool making evidence easier to inspect and a tool improving the final reconstructed behavior. REA demonstrated useful packaging of a particular binary interface. The reconstruction results were achievable with the other approaches too. I would keep that narrower evidence advantage, together with the analysis limits and operational cost, visible in any decision about adopting it. Repeated runs with a corrected, frozen classifier and broader conventional-tool controls would be needed before making a stronger effectiveness claim.
