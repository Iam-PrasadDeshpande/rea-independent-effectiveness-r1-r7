# R7 validation harness review

Scope: read-only review of `evaluator/RUBRIC.md`, `scripts/Validate-R7-v2.ps1`, `scripts/browser-runner.js`, `scripts/Invoke-R7Sandbox.ps1`, and `scripts/Controlled-R7Mcp-v2.ps1`. Paths below are relative to R7. No live arm outputs, submissions, hidden results, or prior experiment findings were inspected. No custom scripts were executed. Only this review document was added; source, freeze, oracle, rubric, and scoring code were not modified. This is a static review, not runtime isolation certification.

## Findings requiring disposition before hidden evaluation

1. **Negative cases can pass because output decoding fails after reconstruction returns successfully.** In `browser-runner.js:64-78`, both `window.reconstruct(...)` and the harness's subsequent `createImageBitmap` of returned bytes share the same catch and become `status: ERROR`. `Validate-R7-v2.ps1:28` accepts a general ERROR with a blacklist of timeout/crash text for invalid-options cases. Consequently, returning invalid bytes rather than rejecting invalid options can earn negative-case credit. The corrupt-input case also accepts output-decode errors containing `image`, `decode`, or `InvalidStateError`, so it does not prove that input decoding was rejected. This conflicts with `RUBRIC.md:9`. Distinguish a rejection from reconstruct itself from fixture generation, output conversion, output decode, filesystem, timeout, and runtime failures. Only the appropriate reconstruction rejection should satisfy a negative case. This is a harness classification defect, not a reason to relax the frozen oracle.

2. **The implemented controller permits five more tool calls than the declared ceiling.** `RUBRIC.md:52` specifies 60 calls, including failures; `Controlled-R7Mcp-v2.ps1:33` increments and permits calls through 65. Actual use above 60 is not established by this review. Reconcile enforcement and separately retain actual counts; do not silently change the frozen run allowance after an arm starts.

3. **The ordinary inspection interface can launch arbitrary commands inside its sandbox despite its advertised “No shell” restriction.** `Controlled-R7Mcp-v2.ps1:18,35` forwards literal arbitrary argv; `Invoke-R7Sandbox.ps1:24` checks only the first executable name and permits `find`. `find -exec /usr/bin/sh -c ...` can execute caller-supplied code without passing through the JavaScript signing path. This is not evidence of escape from bwrap, source access, or external network access: `Invoke-R7Sandbox.ps1:12` still supplies the namespace/mount boundary. It is a concrete limit on the claim that every custom-script execution requires the controlled signer, and may expose more ordinary execution capability than the advertised catalog. Constrain the relevant argv forms or explicitly qualify and consistently authorize this broader in-sandbox execution surface before relying on signature gating as an invariant.

## Stale-output and independence limitations

- **Top-level stale result files are addressed, but directory state is not reset.** `Validate-R7-v2.ps1:13-15` archives only files directly inside the shared evaluator output directory, then copies top-level submission JS. Subdirectories remain, while the HTTP server serves any path beneath `/output` as `/submission/*` (`browser-runner.js:15-23`). If pre-existing nested assets are present, a later submission can resolve them and depend on previous state. `evaluator/submissions/<Arm>` is also created and populated without requiring it to be initially absent/empty (`Validate-R7-v2.ps1:7-10`). This review did not inspect these directories and does not claim contamination occurred. Require clean/manifested directory trees or attest that only the declared top-level files exist. The current archive does prevent straightforward reuse of a previous top-level `result.json` when a new browser run fails before writing one.
- **Input SHA is measured after the untrusted function receives the same mutable object.** `browser-runner.js:65-75` passes `input` directly into reconstruct and only afterwards hashes `result.input.bytes`. A solution mutating that array changes what the evaluator records as the supplied input. Snapshot/hash fixture bytes before invocation and pass a separate copy. This affects provenance and can cause false input mismatch; no tampering is asserted.
- **One clean browser context is created per run, not per scenario.** `browser-runner.js:33,59-80` loads the submitted script once and reuses its page/global state across all cases. The timeout is a Promise.race; timing out does not cancel reconstruct or its workers (`68`). Subsequent cases can run while timed-out work is still active. The reference path creates/terminates a dedicated raw worker per scenario (`browser-runner.js:115-117,161`), so lifecycle isolation is asymmetric. Treat a timed-out reconstruction as an invalid run boundary or isolate subsequent cases; do not interpret subsequent failures as independent observations without qualification. Stateful module caching itself is not an invalid implementation.
- **Sandbox exit status is retained but not used as a validation precondition.** `Validate-R7-v2.ps1:18-20` stores the sandbox reply and proceeds to result parsing. The prior top-level archive means a missing new result fails rather than recycling the previous one; nevertheless, a nonzero exit with a newly written report is not explicitly distinguished from a complete healthy evaluation. Require zero exit plus a fresh, schema-valid report with the expected unique case IDs before assigning a complete bounded-pass disposition.

## Signed subprocess fix and review boundary

The controller's signing operation now uses a distinct `pwsh.exe -NoProfile -ExecutionPolicy AllSigned -File Sign-R7Submission.ps1` process with literal argument construction, closed stdin, bounded wait, exit-code check, and subsequent exact-thumbprint verification of the submitted JS (`Controlled-R7Mcp-v2.ps1:39`). Static inspection supports that this addresses same-process signing invocation/stream interference as designed; no invocation was performed in this review. It does not by itself close the separate `find -exec` surface above.

The reviewed sandbox selects the codec-only artifact mount for reconstruction (`Invoke-R7Sandbox.ps1:9-12`), blocks service workers and browser external requests (`browser-runner.js:33-38`), and uses an unshared network namespace (`Invoke-R7Sandbox.ps1:12`). This review did not enumerate the actual mounted codec subset, prove no unexpected binaries/data exist under the broad read-only `/usr`, `/lib`, or `/vendor` mounts, or verify actual signatures/hashes. These remain execution-evidence obligations rather than established failures.

The rubric appropriately limits the behavioral claim to a pinned shared-codec integration and separates architecture understanding and REA evidence traceability from byte matching. This static review cannot establish actual independent working submissions, a successful REA invocation, runtime blindness, or any arm's score. Original retained files/freeze must remain available alongside any corrective harness version and a precise change record.
