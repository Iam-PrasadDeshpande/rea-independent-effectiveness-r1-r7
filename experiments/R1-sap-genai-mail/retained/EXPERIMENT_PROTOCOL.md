# Bounded pilot experiment

The reference/source reviewers and coordinator are unblinded. They are not experimental investigators. Each experimental investigator is a fresh local Codex exec session with no prior conversation or user/project instructions, ignored user config/rules, memories disabled, and a separately probed Linux permission profile. User authentication was completed through the normal interactive Linux login; no Windows credentials were copied or extracted.

Both receive identical byte-for-byte JavaScript input and the same investigator-prompt.txt. Both request gpt-6.1-sol with low reasoning via Codex 0.160.0. Run order is baseline then REA, sequentially on the same host, avoiding simultaneous investigator CPU contention. Run order/cache effects, model stochasticity and an unfixed hosted model snapshot remain confounders. This is one exploratory pair, not a statistical benchmark.

The POC contains original source and oracle files on the host, but investigator command sandboxes mount only the selected arm's artifact, output/scratch, system runtime and Codex binary. Successful artifact reads/output writes and denied source, oracle, peer-output, authentication-home, artifact writes, DNS-based network and direct-IP network attempts are recorded for each arm. Direct-IP curl reports Operation not permitted. Denied host paths appear absent inside the sandbox. Do not equate read-only mode with hiding source: the restricted readable roots are material.

REA is launched only in its arm through a bubblewrap stdio server with read-only /rea and /artifact mounts, private temporary scratch, clear environment and network namespace isolation. No SAP source/oracle/peer mounts are present there. Codex exposes four static-only MCP operations: analyze_javascript_application, inspect_analysis_view, trace_application_feature and trace_javascript_semantics. Default full REA catalog is not exposed to investigators. The shared prompt directs summary analysis followed by bounded inspection; the prior nonblind smoke-test analysis is not supplied to either investigator.

The source URL, original TypeScript/CDS/documentation, source maps, oracle and reference Git repository are excluded. Ordinary emitted JS identifiers/comments remain unchanged. The minimal investigator package is intentionally non-runnable: dependency runtime, generated CAP service metadata and frontend assets are not supplied. Therefore this experiment assesses backend JS architecture/orchestration recovery; the reference architecture's full OData/auth/UI/infrastructure truth remains outside available investigator evidence.

Each investigator may make up to 20 calls and must return an evidence-grounded report plus a fenced module implementing reconstructAddMails under the same injected dependency contract. No investigator-created script is executed in its session. The coordinator extracts the submitted code as data, signs it with the existing approved certificate, verifies its signature, then runs the private differential oracle offline against the actual compiled handler. Live SAP, HANA, AI quality and production behavior remain excluded.

The 30-item architecture/workflow rubric and eight behavioral scenarios are frozen before runs (hash records under evidence). Independent evaluation uses RECOVERED/PARTIAL/MISSED/INCORRECT and concrete evidence, with unsupported conclusions listed separately. Report actual raw counts, token usage when returned by Codex, elapsed wall time, failures/recovery and unmeasured resources as UNKNOWN. A successful MCP call is not a successful investigator reconstruction, and an absent measurement is not zero cost.
